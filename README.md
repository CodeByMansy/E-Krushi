# e-krushi — Flutter port

This is a straight port of the `com.ekrushi.app` Jetpack Compose project to
Flutter. Screens, state flow, and behavior are kept 1:1 — see the comment at
the top of each file in `lib/` for exactly which Kotlin file it was ported
from and which Android API was swapped for which Flutter package.

| Kotlin (Compose)                  | Flutter                                   |
|------------------------------------|--------------------------------------------|
| `MainActivity.kt`                  | `lib/main.dart`                             |
| `ui/screens/SplashScreen.kt`       | `lib/screens/splash_screen.dart`            |
| `ui/screens/LoginScreen.kt`        | `lib/screens/login_screen.dart`             |
| `ui/screens/ScanScreen.kt`         | `lib/screens/scan_screen.dart`              |
| `ui/screens/HistoryScreen.kt`      | `lib/screens/history_screen.dart`           |
| `ui/screens/AboutScreen.kt`        | `lib/screens/about_screen.dart`             |
| `ui/theme/Color.kt` / `Theme.kt` / `Type.kt` | `lib/theme/app_colors.dart` / `app_theme.dart` |
| `data/Models.kt`                   | `lib/data/models.dart`                      |
| `data/WeatherApi.kt` + `WeatherRepository.kt` | `lib/data/weather_repository.dart`   |
| `MockAuthRepository` (in LoginScreen.kt) | `lib/data/auth_repository.dart`       |

## 1. Prerequisites

- Install the Flutter SDK: https://docs.flutter.dev/get-started/install
- Run `flutter doctor` and resolve anything it flags.

## 2. Get the project files

Unzip this project anywhere, e.g. `ekrushi_flutter/`.

## 3. Generate the native Android/iOS scaffolding

This zip ships only the Dart source (`lib/`) and `pubspec.yaml` — the
platform folders (`android/`, `ios/`) are generated by the Flutter tool
itself so they always match your installed Flutter/SDK versions:

```bash
cd ekrushi_flutter
flutter create . --project-name ekrushi_app --org com.ekrushi
```

This will not overwrite `lib/main.dart` or `pubspec.yaml` — it only fills in
the missing native folders.

## 4. Install dependencies

```bash
flutter pub get
```

## 5. Add permissions (mirrors AndroidManifest.xml)

The original app declared camera and (at runtime) location permissions.
Add the equivalent to the generated native projects:

**`android/app/src/main/AndroidManifest.xml`** — inside `<manifest>`, above `<application>`:

```xml
<uses-feature android:name="android.hardware.camera" android:required="false" />
<uses-permission android:name="android.permission.CAMERA" />
<uses-permission android:name="android.permission.ACCESS_FINE_LOCATION" />
<uses-permission android:name="android.permission.ACCESS_COARSE_LOCATION" />
<uses-permission android:name="android.permission.INTERNET" />
```

Also set the app label to match the original:

```xml
<application
    android:label="EKrushiApp"
    ...>
```

**`ios/Runner/Info.plist`** — inside the outer `<dict>`:

```xml
<key>NSCameraUsageDescription</key>
<string>e-krushi needs camera access to photograph plant leaves for disease detection.</string>
<key>NSPhotoLibraryUsageDescription</key>
<string>e-krushi needs photo library access to select leaf images.</string>
<key>NSLocationWhenInUseUsageDescription</key>
<string>e-krushi uses your location to fetch local weather for disease-risk analysis.</string>
```

## 6. Run it

Plug in a device or start an emulator/simulator, then:

```bash
flutter run
```

Or open the folder in Android Studio (with the Flutter plugin installed)
and click Run — Android Studio will detect it as a Flutter project once
`flutter create .` has been run (step 3).

## Notes on behavior parity

- **Demo mode**: `DemoConfig.useMockData` in `lib/data/models.dart` mirrors
  the Kotlin flag. Disease detection and the login OTP flow both run on
  mock data — no backend required to demo the app. The OTP is always
  `0000` in demo mode, same as the original.
- **Weather**: hits the same free `api.open-meteo.com` endpoint as the
  original Retrofit client, just via `http` directly.
- **PDF report**: generated with the `pdf` package and saved to the app's
  documents directory (rather than the public Downloads folder used on
  Android via `MediaStore`), then opened with the device's default PDF
  viewer via `open_filex`. If you need it in the public Downloads folder
  on Android, add the `android_downloads_dir` handling on top of this.
- **Camera/Gallery**: swapped Android's `ActivityResultContracts` +
  `FileProvider` for the cross-platform `image_picker` plugin, which
  handles its own permission prompts.
